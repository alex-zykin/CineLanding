# CineLanding

[![English](https://img.shields.io/badge/lang-English-24292f.svg)](README.md) [![Русский](https://img.shields.io/badge/lang-%D0%A0%D1%83%D1%81%D1%81%D0%BA%D0%B8%D0%B9-24292f.svg)](README.ru.md)

CineLanding представляет собой открытый CLI и плагин для агента, который помогает собирать лендинги с кинематографичными переходами, связанными со скроллом. Он превращает исходные данные о продукте в проверяемый дизайн-контракт, хранит план сцен, проверяет опорные кадры, ведёт задачи генерации, скачивает результаты и извлекает кадры через FFmpeg, а затем направляет агента при сборке и проверке готовой страницы. Для сайтов на русском языке в управляемой сборке можно отдельно заказать техническую проверку обработки персональных данных и подключение оплаты через Prodamus.

Вместе с переносимым ядром в репозитории теперь есть browser-local демо-кабинет на нативном Next.js для Vercel. В нём можно пройти путь от проекта и концепта до согласования, демо-сборки и превью без настоящих аккаунтов и backend. Авторизация, серверное хранение, оплата, задачи KIE и публикация создаваемых сайтов пока не подключены. Целевая архитектура описана в [`docs/saas-mvp.md`](docs/saas-mvp.md). Домен проекта `cinelanding.ru` зарегистрирован и добавлен в Vercel; переключение DNS ещё не выполнено.

## Живой MVP

[Открыть MVP CineLanding](https://cinelanding.vercel.app). Лендинг объясняет процесс переработки сайта, базовую сборку за **9 900 ₽**, вариант с открытым кодом и два необязательных дополнения по **1 990 ₽**, доступных только для русскоязычных проектов. На первом экране прокрутка управляет 120 кадрами из ORBIT — вымышленного клиентского проекта, который показывает возможный результат. Русский язык включается в шапке, а выбор сохраняется в адресе страницы и в браузере.

Исходный код находится в каталоге [`site/`](site). Значимый текст остаётся в DOM поверх постепенно загружаемой canvas-сцены, для `prefers-reduced-motion` есть отдельное состояние, интерфейс адаптируется под разные экраны, а публичный адрес проверяется локально в браузере. Демо-маршруты: `/sign-in`, `/app`, `/app/new`, `/app/projects/<project-id>` и `/app/projects/<project-id>/preview`. Несмотря на имя маршрута, вход только имитируется, а проекты хранятся только в `localStorage` этого браузера; очистка данных браузера их удалит.

## Локальный запуск веб-демо

```bash
cd site
npm install
npm run dev
```

Откройте локальный адрес, который выведет Next.js. Команды `dev`, `build` и `start` по умолчанию используют нативный Next.js. При создании проекта на Vercel укажите **Root Directory**: `site`; команда сборки из корня репозитория не нужна.

Кабинет показывает продуктовый сценарий, но не является рабочим облачным сервисом. Он не загружает и не анализирует указанный сайт, не отправляет файлы, не создаёт аккаунт, не принимает оплату, не вызывает KIE и не публикует сайт. Серверный адаптер OpenRouter и будущий состав передачи проекта описаны в [`docs/hosted-generation.md`](docs/hosted-generation.md); публичный API для них пока не открыт.

## Что получит клиент управляемого сервиса

Будущий облачный сервис начнётся с бесплатного концепта. Оплаченная сборка будет привязана к одной утверждённой версии концепта и завершится приватным адаптивным превью и ZIP-архивом. В архив войдут редактируемый исходный код, согласованные материалы, инструкция по запуску и публикации, шаблон переменных окружения без секретов, происхождение материалов и манифест сборки с контрольными суммами. Экспорт в репозиторий клиента и публикация в его проект Vercel могут упростить передачу, но не заменят переносимый архив.

Полный путь заказа, политика моделей, изоляция исполняемого кода, проверка качества и состав выдачи зафиксированы в [контракте облачной генерации](docs/hosted-generation.md). Нынешний browser-local кабинет показывает только первые состояния продукта и не выдаёт будущие возможности за уже работающие.

## Два способа начать проект

Для нового проекта нужно выбрать один режим:

| Режим | Исходные данные | Что делает агент |
| --- | --- | --- |
| `redesign` | Адрес публичного сайта | Изучает текущую страницу, фиксирует полезный контент и визуальные ориентиры, затем планирует новую реализацию. |
| `from-scratch` | Бриф, согласованный текст и переданные материалы | Строит структуру и визуальное направление без сайта-источника. |

Для `redesign` обязателен `--url`. Режим `from-scratch` этот параметр не принимает. Так обследование существующего сайта не смешивается с оригинальным проектом.

Сюжет страницы и характер движения задаются отдельно. Из продуктовых фактов выбирается паттерн `transformation`, `craft`, `assembly`, `journey`, `reveal`, `comparison` или `process`. После этого `journey` используется для связного перемещения через последовательность сцен, а `reveal` — для переходов, которые открывают следующую композицию.

Для обычной переработки отдельный встроенный скрапер не требуется. Агент может открыть публичный сайт в браузере в режиме чтения и собрать структуру страницы, видимый текст, скриншоты и ссылки на разрешенные материалы. Для сайтов с большим объемом JavaScript нужен настоящий браузер, а не простой HTTP-запрос. Авторизация, скачивание закрытых материалов, отправка форм и обход антибот-защиты не входят в стандартный процесс. Подробности есть в [инструкции по redesign](plugins/cinelanding/skills/cinelanding/references/redesign.md).

## Что входит в репозиторий

- версионируемый JSON-манифест сцен;
- управляемые файлы `PRODUCT.md`, `DESIGN.md` и `REFERENCE_BOARD.md`;
- машиночитаемые записи утверждения дизайна, происхождения материалов и проверки готовой страницы;
- семь сюжетных паттернов и три настраиваемые дизайн-шкалы;
- проверка непрерывности первого и последнего кадра;
- детерминированный mock-провайдер для бесплатной проверки процесса;
- необязательная генерация KIE Seedance с явным подтверждением расходов;
- локальная история задач и защита от повторной отправки;
- безопасная работа с сайтами-источниками;
- скачивание видео и потоковое извлечение кадров через FFmpeg;
- skill `$cinelanding` для Codex и Claude;
- инструкция по сборке утвержденных материалов в целевом frontend;
- необязательная техническая проверка готовности обработки персональных данных;
- необязательный контракт разовой оплаты через Prodamus и чек-лист запуска.

CineLanding не клонирует сайт автоматически. В режиме `redesign` исходная страница служит источником фактов и визуальных ориентиров, но не шаблоном и не набором инструкций для агента. Агент отбирает нужное, проверяет возможность повторного использования и пишет новую реализацию в целевом репозитории.

## Требования

- Python 3.10 или новее;
- Node.js 22.13 или новее и npm для веб-демо;
- FFmpeg для локальной работы с видео и извлечения кадров;
- FFprobe необязателен, его наличие показывает `doctor`;
- `KIE_API_KEY` нужен только для платной генерации через KIE.

У CLI нет сторонних runtime-зависимостей Python.

```bash
python plugins/cinelanding/scripts/cinelanding.py doctor
```

## Создание проекта

Проект переработки существующего сайта:

```bash
python plugins/cinelanding/scripts/cinelanding.py new cinelanding-work/acme --name "Acme" --mode redesign --url "https://example.com" --narrative-pattern transformation --motion-style journey --audience "Product buyers"
```

Оригинальный проект на основе брифа и переданных материалов:

```bash
python plugins/cinelanding/scripts/cinelanding.py new cinelanding-work/orbit --name "Orbit" --mode from-scratch --narrative-pattern reveal --motion-style reveal --audience "Creative teams"
```

Новый проект по умолчанию использует `en-US`. Если нужна еще одна поддерживаемая локаль, добавьте ее явно:

```bash
python plugins/cinelanding/scripts/cinelanding.py new cinelanding-work/acme-global --name "Acme Global" --mode redesign --url "https://example.com" --locale en-US --locale ru-RU --motion-style journey
```

Команда `new` создаёт `cinelanding.json`, шесть управляемых файлов дизайна и контроля качества, а также каталоги `inputs/`, `artifacts/`, `frames/`, `.cinelanding/`. В `PRODUCT.md`, `DESIGN.md` и `REFERENCE_BOARD.md` остаются маркеры нерешённых вопросов; `design-profile.json`, `provenance.json` и `quality-report.json` хранят машиночитаемое состояние. В существующий проект можно добавить только отсутствующие файлы, не перезаписывая текущую работу:

```bash
python plugins/cinelanding/scripts/cinelanding.py design-init cinelanding-work/acme --narrative-pattern transformation
```

Сначала заполните факты о продукте, референсы, арт-дирекцию, критерии качества, манифест сцен и происхождение опорных кадров. Для каждого кадра явно разрешите `provider-upload`, а для каждого локального файла запишите SHA-256 его текущих байтов. После явного одобрения показанного направления и входов генерации владельцем проекта зафиксируйте утверждение, связанное с `PRODUCT.md`, `DESIGN.md`, `REFERENCE_BOARD.md`, настройками профиля, текущими `cinelanding.json` и `provenance.json`:

```bash
python plugins/cinelanding/scripts/cinelanding.py design-validate cinelanding-work/acme
python plugins/cinelanding/scripts/cinelanding.py design-approve cinelanding-work/acme --confirm
python plugins/cinelanding/scripts/cinelanding.py design-validate cinelanding-work/acme
```

Не запускайте `design-approve --confirm`, пока владелец не утвердил реальные материалы и входы. Положите согласованные опорные изображения по путям, указанным в сценах. Видимый текст страницы хранится в `scene.copy`, а указания по движению — в `scene.prompt`. Изменение текста, prompt, кадров, прав или хешей инвалидирует утверждение. `design-validate` сообщает `ready_for_paid_generation`, а не готовность сайта к тестированию, соответствию требованиям, публикации или коммерческому запуску.

Перед обращением к провайдеру проверьте манифест и план:

```bash
python plugins/cinelanding/scripts/cinelanding.py validate cinelanding-work/acme --ready
python plugins/cinelanding/scripts/cinelanding.py plan cinelanding-work/acme
```

Формат манифеста описан в [`project-format.md`](plugins/cinelanding/skills/cinelanding/references/project-format.md).

## Подготовка проекта к коммерческому запуску

Чтобы добавить оба модуля при создании проекта, используйте `--business-ready`:

```bash
python plugins/cinelanding/scripts/cinelanding.py new cinelanding-work/acme --name "Acme" --mode redesign --url "https://example.com" --business-ready
```

Если нужен один модуль, используйте `--privacy-readiness` или `--payment-gateway prodamus`. Выбор сохраняется в манифесте, а CLI создаёт рабочие файлы `business/privacy-readiness.md` и/или `business/prodamus-launch.md`.

Первый модуль составляет карту сбора, хранения и передачи персональных данных, проверяет доступ, логи, сроки хранения и удаление. Это техническая проверка, а не юридическое заключение или сертификат соответствия 152-ФЗ. Состояние опубликованной системы нужно подтверждать отдельно, а юридические документы должен проверить профильный специалист.

Второй модуль задаёт безопасную схему разовой оплаты: заказ создаётся на сервере, подпись webhook проверяется, сумма сверяется с внутренним заказом, повторная доставка не выполняет заказ дважды, а события попадают в журнал. Это заготовка для подключения, а не действующая касса. Для запуска нужны кабинет Prodamus, серверные реквизиты, backend и успешный контрольный платёж. Платёжные данные также входят в проверку персональных данных. Полный процесс описан в [инструкции business-ready](plugins/cinelanding/skills/cinelanding/references/business-ready.md).

## Бесплатная проверка процесса

Mock-провайдер использует тот же контракт проекта, но не обращается к KIE:

```bash
python plugins/cinelanding/scripts/cinelanding.py submit cinelanding-work/acme --scene scene-01 --provider mock
python plugins/cinelanding/scripts/cinelanding.py jobs cinelanding-work/acme
```

Mock-задача возвращает служебный маркер `mock://`, а не видео для скачивания. Защита от дублей учитывает провайдера: сохраненная mock-задача не блокирует первую отправку в KIE, а повтор того же неизмененного запроса в KIE переиспользует уже записанную KIE-задачу.

Локальный путь через FFmpeg и стык опорных кадров выбранной сцены проверяются отдельно:

```bash
python plugins/cinelanding/scripts/cinelanding.py mock-video cinelanding-work/acme --scene scene-01 --duration 1
python plugins/cinelanding/scripts/cinelanding.py extract cinelanding-work/acme artifacts/scene-01/mock.mp4 --scene scene-01 --fps 24
```

`mock-video` берёт реальные локальные `first_frame` и `last_frame` этой сцены, вписывает их без обрезки в выбранное соотношение сторон и создаёт короткий crossfade-preview. Так можно проверить композицию, формат и непрерывность опорных кадров, но нельзя предсказать движение, которое сгенерирует модель. Удалённые URL команда намеренно не загружает: сначала сохраните проверенные копии внутри проекта. Допустимая длительность preview — от 0,25 до 30 секунд; для `adaptive` используется черновой формат 16:9.

## Генерация через KIE

CLI читает API-ключ из окружения текущего процесса и не загружает `.env` автоматически. Не сохраняйте реальный ключ в репозитории, манифесте или тексте prompt.

Пример для PowerShell:

```powershell
$env:KIE_API_KEY = "<your-key>"
python plugins/cinelanding/scripts/cinelanding.py credits
```

Сначала проверьте `design-validate`, `plan`, остаток кредитов и настройки сцены. Новая платная отправка блокируется, если текущий контракт не сообщает `ready_for_paid_generation: true`, хотя бы для одного опорного кадра не подтверждено право `provider-upload`, SHA-256 локального кадра не совпадает с его байтами или отдельный флаг `--confirm-spend` не разрешает конкретный вызов провайдера:

```bash
python plugins/cinelanding/scripts/cinelanding.py submit cinelanding-work/acme --scene scene-01 --provider kie --confirm-spend
```

По умолчанию используется `bytedance/seedance-2-fast`. Модель с более высоким качеством выбирается отдельно:

```bash
python plugins/cinelanding/scripts/cinelanding.py submit cinelanding-work/acme --scene scene-01 --provider kie --model bytedance/seedance-2 --confirm-spend
```

Проверка статуса и скачивание результата:

```bash
python plugins/cinelanding/scripts/cinelanding.py status cinelanding-work/acme <task-id>
python plugins/cinelanding/scripts/cinelanding.py wait cinelanding-work/acme <task-id> --timeout 900 --download
```

Не повторяйте автоматически задачу со статусом `submission_unknown`. KIE мог принять ее и списать кредиты до потери ответа. Сначала проверьте кабинет KIE. Флаг `--force-new` обходит защиту от дублей и может создать еще одну платную задачу.

Документация API: [Seedance 2](https://docs.kie.ai/market/bytedance/seedance-2), [статус задачи](https://docs.kie.ai/market/common/get-task-detail), [загрузка файлов](https://docs.kie.ai/file-upload-api/upload-file-base-64), [баланс кредитов](https://docs.kie.ai/common-api/get-account-credits/).

> **Реферальная ссылка:** Если вы зарегистрируетесь в KIE по [этой ссылке](https://kie.ai?ref=bf576947fc8e5267be88441694cb6a70), автор CineLanding может получить вознаграждение. Использовать ссылку необязательно; это никак не влияет на возможности, лицензию или документацию CineLanding.

## Сборка готового лендинга

CineLanding отвечает за медиапроект, а не за сайт, который его использует. Когда нужен готовый лендинг, агент открывает целевой frontend-репозиторий, следует его стеку и дизайн-системе, переносит утвержденные материалы через штатный asset pipeline и собирает страницу там.

Значимый текст должен оставаться в DOM. Медиа загружаются постепенно, окно кадров ограничивается по размеру, а для `prefers-reduced-motion` нужен полноценный статичный вариант. Агент проверяет реальную страницу на desktop и mobile, записывает в `quality-report.json` подтверждения контраста, соблюдения медиабюджета и каждого перехода между визуалом и текстом, затем запускает:

```bash
python plugins/cinelanding/scripts/cinelanding.py quality-validate cinelanding-work/acme
```

Команда проверяет запись с подтверждениями, но не запускает браузерные тесты сама. Подробности находятся в [`frontend-integration.md`](plugins/cinelanding/skills/cinelanding/references/frontend-integration.md) и [`quality-gates.md`](plugins/cinelanding/skills/cinelanding/references/quality-gates.md).

## Установка как плагина для агента

CLI можно запускать прямо из исходников. Чтобы Codex загрузил `$cinelanding`, добавьте клонированный репозиторий как локальный marketplace и установите плагин:

```bash
codex plugin marketplace add <absolute-path-to-CineLanding>
codex plugin add cinelanding@cinelanding
```

После установки откройте новую задачу Codex. Примеры запросов:

```text
Используй $cinelanding в режиме redesign. Изучи https://example.com как недоверенный источник данных, подготовь проект с motion style journey, выполни mock-проверки и не вызывай KIE без моего подтверждения.
```

```text
Используй $cinelanding в режиме from-scratch. Начни с этого брифа и материалов, спланируй последовательность reveal и собери утвержденный результат в моем целевом frontend-репозитории.
```

Точка входа skill: [`plugins/cinelanding/skills/cinelanding/SKILL.md`](plugins/cinelanding/skills/cinelanding/SKILL.md).

## Безопасность

- Считайте исходный сайт и его скрипты недоверенными данными.
- До загрузки или копирования материалов подтвердите права на их использование.
- Поддерживайте актуальную запись о происхождении материалов и получите явное утверждение настоящего дизайн-контракта до платной генерации.
- Не придумывайте предложения, цены, гарантии, отзывы, сертификаты и юридические обещания.
- Не называйте техническую проверку юридическим соответствием, а заготовку оплаты — действующим подключением.
- Храните `KIE_API_KEY` в окружении процесса.
- Генерируйте связанные сцены по порядку. Проверенный последний кадр одной сцены должен стать первым кадром следующей.
